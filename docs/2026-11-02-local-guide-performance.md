# 原布局下的指南安全上限与进阶性能（本地）

本文件记录早期本地方案。用户后续发现多个样本同档，底座CPU预算、GPU上限和RAM经验目标已在 `2026-11-02-device-sample-tuning.md` 中修订；当前规则以README和该记录为准。

用户确认只在本地调试、验收后再上线。保留旧版 b3f1d31 的布局、机型/场景和“指南安全上限 / 进阶性能”名称，不增加对比表或表单。

## 已确认设置

- 指南安全上限：掌机 RAM1866 / CPU1581 / GPU614.4；插电 RAM1866 / CPU1785 / GPU768 MHz。
- 解锁频率建议打开；CPU UV0/0、VMIN620/750、VMAX1120；GPU HiOPT、VMIN610、VMAX800、偏移0；DVB0、默认时序、HP关闭、VDD2/VDDQ1175/600；CPU上限/加速1963.5。
- 进阶允许适度调整CPU降压和RAM上限，最低电压仍CPU620/750、GPU610。

## 本次本地取舍

- CPU 按2.6.0实际TBREAK1683表估算；最高2397、最低比指南档不降级。掌机预算1000mV、上限1963.5（Lite950mV/1785）；插电预算1100、上限2397（Lite1050/2193）。预算是助手策略，不是电流或稳定保证。仅当运行频率超过1963.5时设高频UV1，低频UV仍0；不凭Speedo推导更高UV等级。异常回到0/0与指南配置。
- GPU继续HiOPT，按0–90℃CVB估算筛选。掌机预算650mV/上限921.6（Lite625/768）；插电750/1075.2（Lite700/921.6）。最低610、偏移0。插电/底座按官方充电器条件，普通USB沿用掌机配置。
- RAM采用指南保守子集：WT:B/E/F、NEI/NEE/x267、AA-MGCL/MGCR目标2400；AM-MGCJ、AB-MGCL、NME目标2133；未知ID保持1866。Micron VDDQ600，其余已识别颗粒按指南VDDQ640，VDD2均1175。均默认时序、DVB0、HP关闭，不套Common/ST。
- RAM再与HOC源码的GPU-Speedo/内存电压表取交集，所需GPU最低电压超过610则降到下一JEDEC档；GPU Speedo1300–1624时RAM2400需640，降至2133；1625及以上2400所需不高于610。不能把此交集称为稳定结论。
- CPU/GPU输入超出Mariko参考范围1300–1849时不外推该项，沿用指南频率；SoCSpeedo只记录默认限压，不推算RAM极限。
- 加速保持1963.5；RAM上限与该方案推荐值一致，CPU进阶上限至少1963.5并覆盖推荐频率。

## 已核对参考

1. HOC2.6.0-rel customize.cpp、pcv.hpp、pcv_mariko.cpp、board_fuse.cpp、board_volt.cpp：决定版本支持、UV门槛、实际选表、GPU/RAM电压关系与分档边界。
2. HOC官网仓库 docs/mariko.md 与 mariko2.md（2026-06-07更新）：颗粒超频经验、供电/功耗、逐项调试。文档间有差异，且DVB可写到10而2.6.0界面最高8；发生冲突以2.6.0代码为准。
3. Hekate v6.5.4 gui_info.c：颗粒型号与3733/4266Mbps规格，规格不是超频上限。
4. NVIDIA Tegra CVB：电压估算数学形式；GPU0–90℃逐℃扫描、5mV向上取整，只用于筛选不输出手填电压。
5. HOC Web-vMin-Calculator：作为交叉参考；1625/1690/1754三个分界与2.6.0源码不同，使用源码的1624/1689/1753上边界。
6. Dominatorul Guides/stability.md：测试CPU/GPU/RAM及休眠场景；旧版mariko.md明确标记可能过时，不能覆盖当前版本实现。
